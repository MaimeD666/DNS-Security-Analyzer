# Проверки

Алгоритмы и их автоматические тесты ещё не реализованы. Автор каждого модуля проверяет собственную часть. Функциональная приёмка: [docs/acceptance.md](../docs/acceptance.md).

| Модуль | Существенные проверки |
| --- | --- |
| parser | Номер пакета, запрос/ответ, клиент/сервер, фильтрация IPv4 UDP/53, MF/frag, имена, повреждённый контейнер |
| features | PSL и исключения, пустой поддомен, Unicode не подменяется, формулы, [start,end), разные клиенты, два масштаба |
| summary | Только запросы в статистике имён, отдельные ответы, NXDOMAIN, топ-10 с равными частотами |
| detector | >=, минимум два условия, 9/10 запросов, причины с измеренным значением |
| incidents | rules/model/hybrid, None при недостатке данных, транзитивное объединение, уникальные пакеты |
| model | Порядок признаков, нормализатор только train, сериализация, несовместимость схемы, отсутствие файла |
| report и CLI | TXT/JSON, отсутствие срабатываний, нет данных, коды 0/2/3, отказ перезаписи, ошибки пути |
| evaluation | Разделение по сеансам, отсутствие дубликатов, ручные TP/FP/TN/FN, неопределённые метрики |

После добавления содержательных `test_*.py` команда проверки:

```bash
python -m unittest discover -s tests -p 'test_*.py' -v
```

Нулевое число тестов не является успешной проверкой алгоритмов. Для формул и правил используются маленькие ручные эталоны, независимо от генератора обучающих данных.
