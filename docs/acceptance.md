# Порядок приёмки

Обязательные условия установлены разделом 12 [ТЗ](technical_specification.md). Этот файл задаёт форму протокола и не заменяет требования. Испытания ещё не проводились.

## Функциональные проверки

| Код | Предмет |
| --- | --- |
| ПИ-01 | Извлечение DNS-полей и общая статистика на вручную проверенных пакетах |
| ПИ-02 | Границы [start,end), независимость клиентов и базовых доменов |
| ПИ-03 | Десять признаков; абсолютная погрешность чисел не более 1e-6 |
| ПИ-04 | >= для всех условий, сочетание минимум двух условий, граница 9/10 запросов |
| ПИ-05 | Интенсивный и малочастотный сценарии; хотя бы один верный инцидент в hybrid в каждом |
| ПИ-06 | Транзитивное объединение окон и уникальные номера запросов |
| ПИ-07 | Повторная загрузка модели, совпадение TXT/JSON, отсутствие тихой подмены метода |
| ПИ-08 | Ошибки чтения/настроек/модели/записи и отдельный результат при отсутствии данных |

Для каждой проверки фиксируются код, команда, вход и его SHA-256, версия программы, настройки, версия модели, ожидаемый результат, фактический результат и статус. Ни одна строка не отмечается выполненной до реального запуска.

## Данные и метрики

Контрольная часть: минимум 100 пригодных окон каждого класса из минимум 10 независимых сеансов каждого класса. Окна 60/300 секунд, исходящие из одного сеанса, находятся в одной части. Число окон по масштабам указывается отдельно; корреляция двух масштабов не называется независимостью примеров. Разбиение и параметры фиксируются до контрольного запуска.

Обычная активность включает длинные имена и множество уникальных поддоменов. Одинаковые исходные записи не дублируются между частями; домены туннелей контрольной части не встречаются в обучении. Нормализация подбирается только на train, пороги и параметры — по train/validation; test не используется для выбора настроек. Состав частей и происхождение сохраняются в реестре.

Для rules, model и hybrid публикуются confusion matrix (TP/FP/TN/FN), precision, recall, F1 и FPR. В знаменатели входят только пригодные размеченные окна; количество исключённых и неоднозначно размеченных окон указывается отдельно. Метрики считаются на уровне окон, а не объединённых инцидентов. Число обнаруженных инцидентов сообщается отдельно.

Требование к hybrid на зафиксированном test: recall >= 0.85 и FPR <= 0.10. Достижение этих значений ещё не подтверждено. Улучшение нейросетью результатов правил не является предрешённым результатом. При недостижении критерия требования не меняются задним числом; корректировка объёма оформляется новой редакцией ТЗ.

Отдельно выполняется проверка на публичном PCAP туннелирования, не использованном для настройки. Указываются источник, лицензия, воспроизводимая команда и наблюдённый результат. Эта проверка не выдаётся за оценку всех реальных туннелей.
