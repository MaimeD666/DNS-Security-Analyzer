# Контракт данных и модулей

Версия 2.0 от 14 ноября 2026 года. Нормативные требования: [ТЗ](technical_specification.md). Документ описывает будущие интерфейсы; заготовки не являются реализацией. При расхождении требований приоритет имеет ТЗ.

## Результат чтения PCAP

`parse_pcap(path: str) -> dict` возвращает `records: list[dict]` и `counters: dict`. Номер пакета начинается с 1 и соответствует позиции в исходном файле, включая пропущенные пакеты. Записи сохраняют исходный порядок. Парсер не выполняет группировку.

| Поле записи | Тип | Содержание |
| --- | --- | --- |
| `packet_index` | int | Номер исходного пакета |
| `timestamp` | float | Неотрицательное конечное время захвата, секунды Unix |
| `client_ip` | str | Отправитель запроса либо получатель ответа |
| `server_ip` | str | Получатель запроса либо отправитель ответа |
| `domain` | str | Полное ASCII-имя в нижнем регистре без конечной точки |
| `query_type` | str | A, AAAA, TXT, MX и т. п.; неизвестный — TYPE с числом |
| `is_response` | bool | False — запрос; True — ответ |
| `rcode` | int или None | Код ответа; для запроса None |

Счётчики: `total_packets`, `accepted_packets`, `skipped_non_dns`, `skipped_unsupported`, `skipped_invalid`. Для каждого пакета выбирается ровно одна категория. Их сумма, кроме `total_packets`, должна равняться `total_packets`. `accepted_packets == len(records)`.

Порядок категорий: отсутствие распознаваемого DNS — non_dns; распознанный DNS вне IPv4 UDP/53 или в IP-фрагменте — unsupported; оставшийся DNS с непригодным первым вопросом, именем или временем — invalid. Повреждение контейнера — исключение чтения, а не результат с нулём записей. Проверять `frag != 0` и флаг MF. DNS без вопроса пропускается. При нескольких вопросах берётся первый. Корневое имя и пустые метки пропускаются.

Допускаются a–z, 0–9, дефис, подчёркивание и точки между непустыми метками; длины не превышают ограничений DNS. Конечная точка удаляется ровно как признак абсолютного имени. Недопустимые символы не заменяются символом-заглушкой. Сетевые повторы учитываются отдельно.

## Суффиксы и окна

`build_features(records: list[dict], config: dict) -> list[dict]`. Ответы исключаются. Определение базового домена использует локальный PSL с ICANN- и PRIVATE-разделами, правилами wildcard и exception. Копия должна сопровождаться лицензией и SHA-256. Никакой загрузки PSL при анализе. Для неизвестной зоны действует неявное правило `*`; для однокомпонентного имени базовый домен равен имени. В контрактных тестах `a.b.example.co.uk` группируется с `x.example.co.uk`, а `a.one.test` не группируется с `b.two.test`.

Пара группы — `(client_ip, base_domain)`, DNS-сервер не входит в ключ. Для каждого W из `window_sizes` запрос относится к интервалу `[floor(t/W)*W, floor(t/W)*W + W)`. Событие на правой границе попадает в следующее окно. Каждый масштаб обрабатывается отдельно, пустые окна отсутствуют. Окна сортируются по `(client_ip, base_domain, window_seconds, window_start)`.

| Поле окна | Тип | Содержание |
| --- | --- | --- |
| `window_id` | str | Стабильная сериализация `[client_ip, base_domain, W, start]` в JSON без пробелов |
| `client_ip`, `base_domain` | str | Группа |
| `window_start`, `window_end` | int | Полные границы окна Unix |
| `window_seconds` | int | W |
| `packet_indices` | list[int] | Номера запросов по возрастанию без повторов |
| `examples` | list[dict] | Первые пять запросов по `(timestamp, packet_index)` с полями domain, packet_index |
| `features` | dict | Десять признаков в следующем порядке |
| `status` | str | eligible либо insufficient_data |

Порядок признаков: `query_count`, `query_rate`, `mean_subdomain_length`, `max_subdomain_length`, `mean_entropy`, `digit_ratio`, `unique_ratio`, `txt_ratio`, `subdomain_bytes`, `mean_interval`.

Формулы приведены в разделе 5 ТЗ. Для числовых признаков не допускаются NaN и бесконечность. Интервалы рассчитываются по отсортированным временам, в том числе нулевые. Частота всегда N/W, а не N/(последнее время − первое время). Доля цифр взвешивается по суммарной длине строк. Уникальность считается по полному нормализованному поддомену с точками. Энтропия и длина — по поддомену без точек. Пустой поддомен участвует в средних и уникальности; его энтропия и длина равны нулю.

## Общая статистика

`calculate_stats(records: list[dict]) -> dict` возвращает `total_queries`, `total_responses`, `unique_domains`, `top_domains`, `query_types`, `nxdomain_count`. Первые четыре характеристики имён и типов учитывают запросы; `total_responses` и `nxdomain_count` — ответы. `top_domains` — максимум 10 объектов `{domain, count}`, сортировка по убыванию count, затем по имени. NXDOMAIN — rcode 3, независимо от присутствия парного запроса. Счётчики пропусков берутся из результата парсера.

## Решения методов

`detect_rules(windows: list[dict], config: dict) -> list[dict]` возвращает одно решение на каждое окно. Все пять условий сравниваются через `>=`. Срабатывание — не менее `min_signals` выполненных условий при `query_count >= min_queries`. `status` недостаточного окна сохраняется; `suspicious` равен None.

`predict_model(windows: list[dict], model_path: str, threshold: float) -> list[dict]` возвращает одно решение на окно. Для пригодного окна `suspicious = score >= threshold`; для недостаточного score и suspicious равны None.

Общая часть решения: `window_id`, `method` (rules или model), `status`, `suspicious`. Правила дополняют её `signals: list[dict]` с ключами feature, value, threshold. Модель дополняет её `score: float | None`, `threshold: float`. Оценка не называется подтверждённой вероятностью атаки.

Режимы model и hybrid требуют исправной модели и совместимой схемы признаков. Несовпадение схемы, версий или отсутствующий файл — явная ошибка, без тихой замены режима. Сведения об архитектуре, нормализаторе, порядке признаков, пороге, random_state и версиях библиотек сохраняются с моделью. В качестве сериализованной модели принимаются только файлы команды, полученные воспроизводимым обучением.

## Объединение и инциденты

`combine_results(windows, rule_results, model_results, mode) -> list[dict]` возвращает общую оценку каждого окна: window_id, status, rules_suspicious, model_suspicious, model_score, final_suspicious, signals. Неиспользуемый метод имеет значения None. В hybrid итог — логическое ИЛИ; недостаточное окно не получает итогового булева решения.

`build_incidents(windows: list[dict], evaluations: list[dict]) -> list[dict]` объединяет только подозрительные окна одной пары `(client_ip, base_domain)` по условию `next_start <= current_end`. Период расширяется транзитивно. Разные пары никогда не объединяются. Уникальность запросов определяется номером пакета, а не именем или временем. Границы инцидента — границы объединённых окон; фактические времена отдельных событий не подменяют их.

Инцидент содержит `incident_id`, `client_ip`, `base_domain`, `start`, `end`, `window_ids`, `packet_indices`, `query_count`, `methods`, `evidence` (решения и признаки каждого окна), `examples` (первые пять уникальных исходных запросов). `incident_id` — стабильная JSON-сериализация `[client_ip, base_domain, start, end]` без пробелов. Итоговая сортировка по `(start, client_ip, base_domain)`.

## Формирование отчёта

`build_report(metadata, counters, stats, windows, evaluations, incidents) -> dict` создаёт словарь со схемой `report_schema_version: 2`. Поля верхнего уровня: metadata, counters, stats, windows, evaluations, incidents, limitations. Metadata содержит входной SHA-256, режим, снимок настроек, версии программы и модели, время формирования UTC. Объект должен сериализоваться в JSON без специальных Python-типов.

`show_report(report: dict) -> None` выводит краткое представление. `save_report(report: dict, prefix: str, overwrite: bool = False) -> None` сохраняет `<prefix>.txt` и `<prefix>.json` в UTF-8. Файлы не перезаписываются без флага; временные файлы исключают выдачу незавершённого отчёта за готовый. Ошибка записи любого результата завершает операцию кодом 3; уже существующие файлы не повреждаются. Временные метки в данных остаются числами, представление для пользователя — UTC.

## Настройки

Единственная исходная конфигурация — `config.json`. `schema_version == 2`; `window_sizes` — различные положительные целые; `min_queries >= 2`; `min_signals` от 1 до 5; длина, энтропия и частота неотрицательны; долевые пороги и порог модели в [0,1]. Булевы значения не принимаются как целые. Список суффиксов должен существовать в момент анализа. Предельные значения из ТЗ относятся к значениям по умолчанию и явно проверяются отдельно.

## Ошибки

Парсер и вычислительные модули передают исключения вызывающему коду; они не печатают пользовательские сообщения и не завершают процесс. Точка входа связывает ошибки с кодами 2 и 3 из ТЗ. Код 0 допускается при наличии срабатываний и при корректном отсутствии данных. Повреждённый PCAP не превращается в пустой список. Отсутствующая модель в rules не требуется и не загружается.
