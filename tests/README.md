# План проверок

На первой неделе автоматических тестов ещё нет. Проверки добавляет автор каждого модуля; Миша собирает общий набор и сценарии демонстрации. Для начала достаточно стандартного `unittest`, дополнительная зависимость не требуется.

| Модуль | Что проверить |
| --- | --- |
| `parser.py` | Запрос и ответ, исходный клиент, нормализация домена, тип, `rcode`, фильтрация UDP/53, PCAP без DNS |
| `statistics.py` | Только запросы в счётчиках запросов, уникальные домены, топ-10 и равные частоты, типы, NXDOMAIN только по ответам, пустой список |
| `detector.py` | Все три правила, строгое превышение порогов, граница окна 60 секунд, независимые клиенты, несортированные времена, отсутствие двойного подсчёта |
| `report.py` | Читаемый вывод, причина каждого предупреждения, TXT в UTF-8, ошибка записи файла |
| `main.py` | Общий запуск, неверный путь, пустой/повреждённый PCAP, файл без DNS |

Точные границы и примеры — в [контракте](../docs/contract.md). Для независимых проверок статистики и детектора используй вручную заданные записи, без зависимости от реализации парсера.

После добавления файлов `test_*.py` запуск из корня проекта:

```bash
python -m unittest discover -s tests -p 'test_*.py' -v
```

Пока файлов тестов нет, эта команда найдёт ноль тестов — это не проверка корректности будущего анализатора.
