# Исходные данные и разбиение

Динда Степан подготавливает PCAP и метки сеансов. Крутов Кирилл строит числовую выборку, задаёт train/validation/test и проверяет независимость частей.

Каждый сеанс в manifest.json содержит session_id, path, sha256, source_type, generation и labels. Для синтетических данных generation содержит команду, параметры и seed. Для внешних данных добавляются source_url и license.

Labels содержит client_ip, base_domain, start, end, label: 0 — обычная активность, 1 — туннелирование. Интервалы [start,end) задаются в Unix-секундах. Окно получает метку, если все запросы имеют одну известную метку. Смешанные и частично неразмеченные окна исключаются из обучения и оценки с отдельным счётчиком.

Разбиение сохраняется в splits.json: session_id сопоставляется train, validation либо test. Все окна и оба масштаба одного сеанса остаются в одной части. Дубликаты исходных записей исключаются. Домены синтетических туннелей test отличаются от train и validation.

Состав: обычная активность, обычная активность с длинными и уникальными поддоменами, интенсивная и малочастотная передача. Не менее 10 сеансов каждого класса. Test содержит не менее двух сеансов и 20 пригодных окон каждого класса. Подробности: [приёмка](../docs/acceptance.md).

PSL используется из встроенного снимка tldextract 5.3.0. Параметры TLDExtract: suffix_list_urls=(), cache_dir=None, include_psl_private_domains=True. Отдельная загрузка списка не требуется. Для неизвестного суффикса последние две метки выделяются явно по правилу из ТЗ.
