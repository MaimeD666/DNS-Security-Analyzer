# Данные и разбиение

Набор ещё не подготовлен. `manifest.json` — пустой реестр, а не готовая выборка. Стёпа отвечает за происхождение и разметку сеансов, Миша — за построение выборки и разбиение, Илья проверяет независимость контрольной части.

Каждый сеанс получает `session_id`, `path`, `sha256`, `source_type` (synthetic либо public), `source_url`, `license`, `generation` (команда, параметры, seed при наличии), `split` (train/validation/test/external) и `labels`.

Разметка labels содержит client_ip, base_domain, start, end, label (0 — обычная активность, 1 — туннелирование). Интервалы [start,end) задаются в Unix-секундах. Окно получает метку только тогда, когда все его запросы имеют одну известную метку; смешанные или частично неразмеченные окна исключаются из обучения и оценки с отдельным счётчиком. Пропусков разметки нельзя молча считать обычной активностью.

Разделение производится по сеансам до создания окон. Все масштабы и части одного сеанса остаются в одном split. Домены туннелей test не встречаются в train. Исключаются дубликаты исходников; близкие копии одного синтетического сеанса не считаются независимыми. Используемые методы генерации и их отличия между частями описываются явно.

Минимум test: 100 пригодных окон каждого класса из 10 независимых сеансов каждого класса. Учитываются оба масштаба с отдельным числом окон. Не менее одного независимого публичного PCAP проверяется отдельно в external без настройки по нему. Требования: [приёмка](../docs/acceptance.md).

При реализации добавить `public_suffix_list.dat` из Public Suffix List, его лицензию, дату получения и SHA-256. Сейчас файла нет, это явно незавершённая часть. Список используется локально с ICANN- и PRIVATE-разделами; автоматическая загрузка при анализе запрещена. Библиотека разбора выбирается и закрепляется после проверки совместимости.
